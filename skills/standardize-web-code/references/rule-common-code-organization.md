# 代码组织、抽象与状态

- 一个功能从上到下应能追踪输入、状态、派生数据、动作、副作用与输出。保持最少真实状态；可派生数据不重复存储。
- 不为可由唯一事实直接得出的展示或业务状态再维护镜像变量。例如由 `cardList.length > 0` 决定列表是否展示时，不再维护 `isShowCardList`；只有展示意图独立于列表内容、需要过渡态或存在明确业务语义时，才保留独立状态并写明原因。
- 至少满足一项才抽取：两个独立调用方、领域不变量/兼容边界、外部系统隔离、可独立理解与测试的复杂度，或页面中明确独立的大区块。否则让逻辑靠近唯一调用点；避免单次使用的透传函数、纯改名包装、空 Service、单 effect 的 Hook/Composable。
- 每一层都必须减少调用方需要理解的复杂度；若包装只把参数原样转交、隐藏简单控制流或迫使读者跳转才能理解业务，就内联或合并。用守卫式返回、具名派生值和小而完整的领域分支压平嵌套，不以机械的函数长度或层数阈值拆分。
- 声明变量、函数、Hook/Composable 前先确认其表达的事实、状态或复用边界是否不可替代。将只服务一处、只有一两行且不会提升可读性的零碎函数内联；不要为机械拆分制造阅读时必须来回跳转的控制流。
- 多阶段异步流程使用显式状态机或联合类型；一起处理加载、成功、错误、取消和重置。正确清理替换请求、定时器、订阅、流及 DOM 资源。
- 全局样式只放 Token 与基础规则；功能样式随功能或组件。先使用语义化 HTML 和既有设计系统，避免无故新建第二套组件前缀或样式体系。
- 删除样式前核实模板/JSX、动态 class、CSS Modules/Scoped CSS、变体、Portal/Teleport、过渡类与 keyframes；删除代码前同时检查再导出、动态导入、路由、插件扫描、配置、测试和依赖注入。
