# TypeScript 与数据建模

- 以仓库现有 `tsconfig` 为准；新项目优先启用 `strict`。渐进迁移时收紧受改动模块，不用全局关闭严格检查掩盖问题。
- 在 HTTP、表单、环境变量、消息队列和持久化等不可信边界解析并收窄 `unknown`；不要以 `any`、双重断言或无校验断言跨越边界。断言仅可表达已验证或编译器无法推断的事实，并保持局部且注明理由。
- 把可选、空值、单位、时区、分页、权限和版本等业务事实编码进类型或校验；不要用 `!`、隐式默认值或宽泛字符串悄悄抹平不确定性。
- 用可判别联合类型表示互斥状态，并在 `switch` 中穷尽处理；不要让加载、成功、空态和错误以相互矛盾的布尔值并存。
- 类型服务于真实领域与公开契约。优先推断局部实现类型；为跨模块边界、复杂返回值、泛型约束和公共 API 写明确类型。不要为实现细节批量添加冗余注解。
- 区分输入模型、领域模型和输出模型仅在边界确实不同；禁止把持久化对象或整个请求体不加选择地透传到响应或写入层。
